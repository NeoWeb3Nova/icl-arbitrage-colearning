## 做了什么

1. 阅读并整理套利第一性原理：价差只是线索，必须扣除 Gas、协议费、桥费、滑点、延迟、失败成本和资金占用成本。
2. 使用 LI.FI 只读 `/quote` 接口构造两腿回环：
   ```text
   Ethereum ETH → Arbitrum USDC → Ethereum ETH
   ```
3. 编写并运行 `tools/virtual-arbitrage.py`：
   - 第一次请求：ETH → USDC；
   - 第二次请求：使用第一腿 `toAmount` 进行理论卖出；
   - 第三次请求：使用第一腿 `toAmountMin` 进行保守卖出；
   - 保存两腿原始响应、路由、费用和计算结果。
4. 使用 `Decimal` 和最小单位整数计算，避免浮点金额误差。
5. 修复证据文件保存问题：`--save` 的父目录不存在时自动创建。

## 发现了什么

- 单向 `ETH → USDC` 报价只能证明跨链兑换路径，不能证明套利；必须补齐 `USDC → ETH` 卖出腿。
- 两腿资产必须连续：
  ```text
  leg2.fromAmount = leg1.toAmount
  leg2-conservative.fromAmount = leg1.toAmountMin
  ```
- `toAmount` 是理论到账数量，`toAmountMin` 才适合做保守判断。
- LI.FI 报价中的部分费用可能已经包含在到账数量中，不能再次从净收益中重复扣除。
- “能完成两腿报价”不等于“存在正收益机会”。本次两腿闭环的结论是无正收益。

## 遇到了什么问题

### 问题 1：最初只有单腿证据

- 原因：已有 Demo 只请求 `Ethereum ETH → Arbitrum USDC`。
- 处理：补充反向 `Arbitrum USDC → Ethereum ETH` 报价，并让第二腿输入自动继承第一腿输出。

### 问题 2：保存 JSON 时目录不存在

- 原因：从 `tools/` 目录运行时，`--save outputs/...` 被解析为 `tools/outputs/...`，目录尚未创建。
- 处理：脚本使用 `Path(...).parent.mkdir(parents=True, exist_ok=True)` 自动创建父目录。
- 验证：使用与实际运行相同的工作目录和命令成功写入 JSON。

结算公式：

```text
净收益 ETH = 第二腿最终到账 ETH - 初始投入 ETH
```

严格结论：在本次报价时间和 0.1 ETH 规模下，扣除报价中体现的成本并采用保守到账数量后，没有观察到正收益套利。
